# Contributing to ResumeIQ

Thanks for your interest in contributing. This guide explains how to propose changes and collaborate effectively.

## Getting started

- Read README.md and SETUP.md to get the project running.
- Check open issues or create a new issue to discuss significant changes.

## Development workflow

1. Fork the repo and create a feature branch from main.
2. Make focused changes with clear commit messages.
3. Keep changes scoped; split large changes into multiple PRs.
4. Ensure the app builds and tests pass before opening a PR.

## Code style

- Follow the existing TypeScript and React patterns in the codebase.
- Prefer small, readable components and utilities.
- Keep function and variable names descriptive.

## Testing

- Add or update tests when changing behavior.
- If no tests exist for the area, describe how you validated the change.

## Submitting a PR

Include the following in your PR description:

- Summary of changes
- Motivation and context
- Testing performed

## Reporting issues

- Provide steps to reproduce, expected behavior, and actual behavior.
- Include logs or screenshots if relevant.

## Security

If you discover a security issue, do not open a public issue. Email the maintainers at frankmendezresources@gmail.com.
